3 · 미션 상태도

토요일 청소 한 번 = 미션 하나

사전 점검 항목: 로봇 3대 온라인·배터리 ≥ 90%·오류 없음, 도크 먼지봉투 < 90%, 뒷문 열림(CAM4 영상에서 문틀 영역 판별), 오늘이 제외일 아님, 본당 안 사람 없음(카메라 움직임 감지, 선택). 실패하면 BLOCKED로 가서 관리자에게 알리고 30분마다 다시 점검, 2시간 지나면 SKIPPED.

# fleet/door.py (요지)
class DoorMutex:
    holder: str | None = None
    queue: deque[str]          # FIFO

    def request(self, rid) -> bool:
        if rid not in self.queue: self.queue.append(rid)
        if self.holder is None and self.queue[0] == rid:
            self.holder = self.queue.popleft()
            return True
        return False            # 호출자는 pause 후 대기

    def release(self, rid):     # 태그가 문 영역을 0.6 m 벗어나면
        if self.holder == rid: self.holder = None

    def watchdog(self, now):   # 90 s 넘게 점유 → 강제 해제 + 경고
        ...

문 영역은 F 좌표 사각형 x 1.6–3.0, y 17.2–18.6. 잠금 요청은 로봇이 문 0.8 m 앞에 왔을 때, 해제는 태그(또는 융합 위치)가 반대쪽 0.6 m를 지났을 때.

7 · 알고리즘

구역, 줄, 재배분, 청소율

줄(pass) 만들기

for y in arange(D - r - 0.03, zone.y_front, -0.33):
    iv = free_intervals(zone.x1, zone.x2, y,
                        margin = r + 0.03)      # 금지 구역 빼기
    iv = [s for s in iv if reachable(mid(s), y)] # 문에서 이어진 칸
    passes.append(longest(iv))               # 뒤 → 앞 순서

r = 0.175 m, 간격 0.33 m (흡입 폭 0.35 m보다 약간 좁게 겹침). 실제 로봇에는 줄 대신 "구역 사각형 + 방향"으로 넘기고, 줄은 서버의 진행률 계산과 재배분 단위로만 씁니다.

재배분 (work stealing)

def next_pass(robot):
    p = robot.queue.popleft()            # 자기 줄: 뒤부터
    if p: return p
    victim = max(others, key=len(queue))
    if len(victim.queue) >= 3:
        return victim.queue.pop()       # 남의 줄: 앞부터
    return None                          # → RETURNING

양쪽 끝에서 가져가므로 두 로봇이 같은 줄에서 마주치지 않습니다. 시뮬레이션에서 R1이 약 47분에 끝나 다른 구역 앞줄을 도와, 전체 시간이 약 75분 → 67분으로 줄었습니다.

청소율

  • 바닥 20 × 18 m를 10 cm 칸 36,000개로 나눔.
  • 분모: 로봇 중심이 문에서 이어져 갈 수 있는 칸(벽·금지 구역에서 r만큼 떨어진 칸)을 flood fill → 반지름 r로 팽창. 약 234 m².
  • 분자: 융합 위치를 5 cm마다 찍어 반지름 r 원 안의 칸을 칠함. 태그가 보인 구간은 confirmed, 가려진 구간은 estimated.
  • 공개 청소율 = (confirmed + estimated) ÷ 분모. 관리 페이지에는 둘을 나눠 표시.

정체·오류 감지

  • 90 s 동안 이동 < 0.2 m이고 상태가 cleaning → STUCK 경고.
  • HA 오류 엔터티(바퀴 걸림, 브러시 엉킴, 낭떠러지) → ERROR.
  • 금지 구역 안쪽 0.3 m로 들어감 → 즉시 pause + 경고 (가상 벽 설정 확인 필요).
  • 로봇끼리 0.6 m 안 + 서로 접근 중 → 뒤 로봇 5 s pause.
8 · 위치 융합

카메라 + 로봇 자체 위치 칼만 필터

  • 상태 x = [px, py, vx, vy, θ], 등속 모델, 20 Hz 예측.
  • 카메라 측정 z_cam = (px, py, θ), R = (σ_cam)², σ_cam은 오차 모델에서 위치별로 계산 (약 1.2–2.0 cm).
  • 로봇 자체 위치 z_rob = T_k(p_dreame), R = (8 cm)², HA가 줄 때만 (보통 2–5 s 간격).
  • 의자 밑 제약: 위치가 의자 영역이면 의자 좌우 다리 사이(±5 cm)로 투영.
  • 측정 시각은 RTSP 타임스탬프(NTP 동기)로 맞추고, 늦게 온 측정은 상태를 되감아 다시 적용.
  • 3 s 넘게 측정이 없으면 공분산이 커지고, 관리 페이지에 "추정" 표시.

12 · Windows 11 개발

Docker Desktop(WSL2)에서 본당과 로봇 3대 띄우기

설치 순서

  1. wsl --install 후 재부팅
  2. Docker Desktop, WSL2 백엔드, 메모리 16 GB 이상
  3. WSL 안에서 git clone https://github.com/benchvue/cleaning
  4. cd cleaning/edge && docker compose --profile sim up
  5. 브라우저: localhost:6080(Gazebo), localhost:8080(웹), localhost:8000/docs(API)

지금 바로 되는 것

  • 저장소 루트에서 python -m http.server 8000 → 모든 페이지와 브라우저 시뮬레이션(sim.js)이 서버 없이 동작
  • layout.js의 숫자를 바꾸면 성도 페이지, 관리 페이지, 오차 지도가 함께 바뀜
  • Gazebo 월드는 다음 단계에서 sanctuary.yaml로 자동 생성
